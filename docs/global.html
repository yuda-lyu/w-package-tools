genDocsDist(optopt) → {Object}

Description:

  • 複製發布檔（dist）至docs，給各專案之建置腳本使用（取代各專案自寫之複製dist）

    各自有套件以自己的gh-pages提供dist（站台網址為https://擁有者.github.io/套件名/dist/檔案），故發布時須把./dist/全部檔案（含子資料夾與.map）複製到./docs/dist/， 隨docs提交並經bin/gh-pages部署（bin/gh-pages只部署docs，不另提供dist）。依循genDocsExams複製examples至docs/examples之方式。 於script.txt插在git add之前、所有建置dist之列之後（cleanFolder於前段清空dist，至此dist才重建完成）。

    1. 先檢測，後寫入：dist資料夾不存在（或不是資料夾）、其內沒有任何檔案（含只有空資料夾或只有連結）皆拋錯；目標資料夾位於來源資料夾之內、來源資料夾位於目標資料夾之內（含相同）亦拋錯（連結解開後再判定一次），皆不更動任何檔案。
    2. 清空目標資料夾（不存在則建立；以cleanFolder清空，失敗即拋錯），再把fdDist內全部檔案複製過去（保留子資料夾，位元組原樣複製，含.map）。
    3. 不跟進連結（符號連結、junction），遇到則略過並列入warnings。空資料夾不複製。

    路徑相對於cwd（發布列一律於套件根執行）。結果同時以console.log印出一行摘要。

    opt本身為undefined或null視為未給；其他非一般物件（字串、數字、布林、陣列）拋錯。opt各鍵為undefined或null取預設；給了而型別不符者視為未給、改用預設（不拋錯）， opt.debug為true時另於warnings說明（'invalid opt.鍵: must be 種類, using default'，不含傳入之值）。

    失敗即拋錯（Error物件，帶code），且先於任何寫入：opt為非一般物件為'WPT_DOCS_INVALID_OPT'；dist不存在或不是資料夾為'WPT_DOCS_DIST_NOT_FOUND'； dist內沒有任何檔案為'WPT_DOCS_DIST_EMPTY'；目標與來源重疊為'WPT_DOCS_PATH_OVERLAP'。清空目標失敗為cleanFolder之'WPT_CLEAN_FOLDER'（此時目標可能已部分清空）。

Description:

  • 產製範例頁至docs，給各專案之建置腳本使用（取代各專案自寫之toolg/gDocsExams.mjs與gDocExams.mjs）

    範例頁作為靜態網站（gh-pages）自給自足，不依賴npm之CDN：

    1. 把fdSrc內檔案複製到fdTar（保留子資料夾；只有副檔名在extsText內者才讀成文字改寫，其餘原樣複製）。
    2. 本套件自身之發布檔（dist）由genDocsDist（toolg/genDocsDist.mjs）複製到fdTarDist（站台上之dist/），本函數不複製dist，也不檢查dist是否已建置（與dist建置之先後次序無關）。 範例檔內自身之dist相對路徑引用（如'../dist/xxx.umd.js'）保持原字串，不換成CDN；fdTarDist為dist在站台內之位置，預設'./docs/dist/'。 若引用相對於範例檔所在位置，在複製後不再指向fdTarDist之同一檔（如範例檔在專案根、引用'dist/xxx.umd.js'，複製到docs/examples後失效），則改寫為指向fdTarDist之相對路徑。
    3. 範例檔內指向其他自有套件（wsemi與w-開頭）之jsDelivr或unpkg網址（含未釘版、@latest、@x.y.z，含無協定之//開頭）， 以及本套件GitHub擁有者（取自package.json之repository）之gh-pages網址'https://擁有者.github.io/套件名/dist/…'（/dist/以外之路徑視為導覽連結，不動）， 一律改寫為'https://擁有者.github.io/套件名/dist/檔案'（自有套件皆同一擁有者，取本套件之擁有者；不釘版、一律https），不複製其檔，本機node_modules有無該套件皆然；網址之?查詢與#片段、%編碼保留。 路徑非單純之/dist/檔案者（gh-pages站台只提供dist/）、擁有者不明（無repository）保留原網址並列入warnings。 指向本套件自身之此類網址（路徑須以/dist/開頭）改指fdTarDist之同一檔。keepCdn內之套件（預設w-demores，資源型、檔案大）保留原網址。

    套件名取自package.json之name。複製只增不刪，不清空任何目標資料夾（docs由各專案之建置腳本先清空）；相同路徑之檔會被覆蓋。 不跟進連結（符號連結、junction），遇到則略過並列入warnings。結果同時以console.log印出。

    opt本身為undefined或null視為未給；其他非一般物件（字串、數字、布林、陣列）拋錯。opt各鍵為undefined或null取預設；給了而型別不符者視為未給、改用預設（不拋錯）， opt.debug為true時另於warnings說明（'invalid opt.鍵: must be 種類, using default'，不含傳入之值）。

(async) parfor(fpWorker, jobs, optopt) → {Promise}

Description:

  • 輕量持久 worker pool 平行執行器,用原生 worker_threads 把 CPU 密集計算分散到多核心,免任何編譯步驟

    機制: · 免編譯 ESM worker:new Worker(URL)直接跑 .mjs 檔,worker 內可正常 import 專案模組與 node_modules。 · 持久 pool:每個 worker 只建立一次(import core、模組級預計算、initData 注入都只付一次),跑完整批工作才 terminate;對比「每批新建 worker + eval bundle」省去重複啟動 / 解析 / 預計算成本。 · 動態派工:閒置的 worker 自動領取下一個 job(內建負載均衡,不需 caller 預先平衡 job 順序)。 · lifecycle 對稱:全部完成(或失敗)一律 terminate 所有 worker,直跑 node 不會 hang。

    worker 協定(worker entry 檔須遵守):

    1. 經 workerData 收 initData(一次)。
    2. 收 { k, job } → 計算 → 回 { k, r }。
    3. 單 job 失敗回 { k, err }(err 為字串)→ 不炸批,主程序印錯後續跑。
    4. worker 載入 / init 失敗(import 錯、workerData 處理 throw)→ 整批 fail-fast 拋錯(不默跑)。
    5. worker 不得自行退出:整批完成前之任何退出(含 process.exit(0))、worker 建立失敗、結果反序列化失敗、job 無法結構化複製、cb 拋錯 → 皆整批 fail-fast 拋錯並 terminate 全部 worker(不懸置、不遺留)。
    6. worker entry 須綁 parentPort.on('messageerror', (err) => { throw err }):job 於 worker 端反序列化失敗時該 job 不會送達、主程序無從得知,拋出即成 worker 未捕捉例外 → 經第 4、5 條之 error 路徑整批 fail-fast(帶原始錯誤);未綁者遇此情形整批懸置。

    適用:CPU 密集的純計算(大量迴圈、數值運算、回測撮合),且工作可拆成多個彼此獨立的 job 不適用:I/O 密集任務(讀檔、網路請求),這類用單執行緒 Promise 並行即可,開 worker 反而多付啟動與傳輸成本
